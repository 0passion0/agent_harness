## A. G1：先修宿主崩溃终态

- **证据**：`application.ts:739–742` 清 running；`finish:818–841` 才持久化终态且依赖 backend snapshot。启动已在 `623` 写 active_run，优先复用，不新增账本。
- **已实施方案**：普通完成和重连后的失败归档共享本地记录构造；崩溃分支不执行 RPC，先保存最新 active_run，当前会话重开时核对 durable interrupt 后再归档 failed 或恢复审批。不能仅凭内存未收到中断通知就宣判失败。
- **替代**：建立持久事件账本并重建所有视图。暂不选：现有 Checkpointer 与 Saved 足以解决已见问题，新增第二事件源成本更高。
- **已验证测试**：fake backend 在模型等待/工具等待时发退出；重连后 failed record 恰好一份；重复退出/迟到终态不重复；无运行时退出不生成幽灵 run；原有 run ID/时间/records 保留；审批通知已送达/未送达两种情况都可恢复，完成后只有一份记录。另有真实 Python bridge 强制终止通知检查；尚未做真实模型运行中硬杀的端到端检查。
- **集成与失败注入**：独立临时项目启动真实 Python backend，在可控等待工具中强制终止，重启并打开当前会话；确认最后 checkpoint 可读、失败轮记录存在、工具计数未增加。另测 Electron 重启，不等同 Python 子进程退出。
- **验收**：上述可控案例 100% 满足状态断言；不把 SIGKILL 前尚未持久化的模型 token/事件伪称完整。
- **回滚**：仅撤回宿主结算提交；不删会话、不回滚 Store、不重新执行业务工具。

## B. G3：先证明压缩是否丢失任务内容

- **证据**：现有 `completed` 不判断领域正确；历史 EVALUATION 文档报告问题，但本轮无新真实模型实验。
- **首选**：在现有多轮回放增加明确的原始范围、关键数字、文件路径、方法选择与产物内容核对。
- **替代**：更换摘要器、改为新 Context Manager 或缩短阈值。暂不选：尚未定位是哪一层造成质量损失，可能只是模型/提示/领域校验问题。
- **单元测试**：消息/工具协议配对、卸载后的路径可读、单条超大输入、系统提示和 tools 占用、profile 小窗口、usage 缺失。
- **集成/边界**：固定 fake model 验证触发顺序；真实模型多轮案例跨过压缩阈值，检查任务约束/数字/交付物一致性。若失败才修改相关提示/策略一处。
- **验收**：质量断言全部通过后比较含摘要和回读的总 token、延迟；低 token 但失败不算收益。
- **回滚**：保留 baseline 配置及任务哈希，单独撤回候选摘要参数/提示；不重写历史消息。

## C. G2：已确认并实施 handler 异常收尾

- **证据**：普通 step Exception 已转 failed state；GraphBubbleUp 保留中断；hook/图异常可能逃逸，绕过 mark。
- **已实施**：handler 逃出的普通异常记 failed、取消记 cancelled，再原样重抛；GraphBubbleUp 保持原生控制流；成功/错误回执复用同一 task 授权收尾入口。后续 G2b 分离内部校验与启动，前置短路不启动、不消耗批准，缓存仍先授权；同步/异步异常、实际取消、原生 ToolNode、checkpoint 恢复和并行重复边界已验证。无匹配 ToolMessage 的返回仍待另行处理。
- **替代**：handler 的 finally 一律 finish/consume。拒绝该方案：会把可恢复审批当作失败，并改变授权消费时机。
- **实际范围**：`engine/policy.py`、`tests/test_tool_authorization_lifecycle.py`；未修改 `common/workflow.py`。用户已按仓库规则明确确认此次特殊异常处理，后续范围变化仍独立评审。
- **验收**：终态与审批消费一致；same run 和 new run 行为可解释；没有新自动重试；原异常传播保持约定。
- **回滚**：独立策略提交；进程内记录不进行历史补偿/批量修复。

## D. G4 / G5：只有需求成立才实施

隔离执行先明确可信主体、文件挂载、网络、凭据、进程树及 artifact 回传。最小试点只替换一个执行边界；用禁止访问、超时残留进程、合法科学计算三类用例验收，不能仅凭 cwd 或路径验证通过宣称沙箱。

预算先测 root/summary/subagent 用量是否完整，再定义请求前允许条件和响应后核算。保留默认超过 30 次调用的行为；需要 opt-in 限额时明确作用域和续跑规则，不能默默新增默认限制。真实金额封顶需供应商计费与输出约束证据。

## 推进门槛

每一轮只实施一个机制：复现 → 写明契约 → 最小变更 → 定向单元/集成/失败检查 → 检查 diff → 记录验收和回滚。相邻契约未明确前，不批量重构。G1 可以先完成而不等待七项目全量审计；本轮已经完成与其相关的定向对比，但尚未开始该修复。
