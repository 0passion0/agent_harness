# 后端编码规范

目标：让代码的职责、依赖和失败后的收尾位置直接可见。复用 Deep Agents 和现有库，优先删除重复状态与分支。

## 方法与类

- 生产逻辑通过类提供，每文件最多一个类，不定义模块函数或嵌套函数。
- 方法完成一个可命名操作；按校验、准备、执行、提交、返回组织，优先提前返回。行数不是拆分依据。
- 有资源、配置或可变状态用实例方法；无状态计算用静态方法；替代构造或依赖类配置才用类方法。
- 构造参数声明依赖。可选参数优先使用关键字参数；不把整个请求字典传入底层。框架规定的回调签名除外。
- 对外暴露完整操作，内部状态使用下划线。禁止跨类调用私有方法或直接修改任务、作业容器。
- 保留框架继承，不为共享几个方法增加业务基类。可独立变化的能力通过组合连接，不增加 DI 容器。

## 类型与失败

- 公共方法标注输入和返回类型；固定内部记录使用数据类，开放 JSON 保留 JSON 形态。
- 外部输入在边界校验，内部使用已验证类型；不为确定类型编写猜测性的转换和容错分支。
- 成功直接返回数据，不能恢复的失败抛出异常；协议和工具适配按各自契约转换。不增加通用结果包装。
- 不吞掉取消和框架审批中断，不将有副作用的工具执行纳入模型重试。
- Any 限于第三方适配和开放载荷。不得全局关闭诊断或用无依据的 cast 掩盖错误。
- 第三方声明缺口只能在对应适配点局部标明原因；不能隐藏本项目的类型错误。

## 生命周期与数据

- 创建资源的一方负责关闭，借用方不关闭。任务、迭代器、线程及子进程清理结束后才发送终态。
- 配置周期资源、单次运行资源、持久化会话状态分别管理。暂停状态以框架检查点为准。
- 每个 thread_id 至多一个活跃运行，不同会话可以并行；记录和回调按会话、任务隔离。共享文件写锁只用于保护同一路径，不能充当全局任务锁。
- 写文件必须先校验、再提交。保留原子替换、权限、BOM、换行和协作取消；多文件失败须报告已提交部分。
- 重构不得清空会话、数据库、附件和产物。只采用当前框架契约，不保留历史状态别名或中间件身份；协议和恢复边界变化必须记录。
- Python 和 Shell 使用宿主用户权限，文件工具的权限检查不是进程沙箱。

## 依赖与说明

- config 和可信身份契约是叶子；execution 不依赖 filesystem、storage 或桌面；filesystem 不依赖 bridge。
- storage 只管理状态存储和检查点；middleware 适配框架钩子；core/compose 负责装配；runtime 负责运行与会话。
- Pydantic 数据模型（含 BaseSettings 和原生 Schema 的子类）全部置于 models 包，由 models/__init__.py 按原类名统一导出，调用者使用 from vertical_harness.models import 类名，不做别名或旧路径转发。其他包入口不提前加载宿主。
- 中文说明只记录职责、不变量、副作用和失败边界，不重复类型注解、作者日期和显然的步骤。
- 已知限制用 `shortcut: 限制，何时升级` 解释，不为未来需求预建抽象。

## 验证

每次修改同步迁移调用者、测试、配置和导出。先运行受影响测试，最终运行全部 pytest、Ruff 和全包 mypy；协议改动同时验证桌面。测试检查行为和清理结果，不锁定私有拆分方式。
